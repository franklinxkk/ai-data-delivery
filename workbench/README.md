# 本地语义工作台

本地单人项目编辑器。使用 Python 标准库和项目已有的 PyYAML；无需数据库服务、Node、CDN、AI API 或 npm build。SQLite 文件是项目唯一的模型版本源，语义模型、资料附件、场景、确认、检查结果均保存在指定项目目录。

## 启动

```bash
python -m pip install -r requirements.txt
python -m workbench.serve --project ./workbench-projects/my-project
```

在终端打开工作台打印的本机 URL。工作台只绑定 `127.0.0.1`，关闭进程后项目文件保留。要继续编辑时，以同一目录重新启动。项目备份包含原始导入资料和可能的演示数据；交付 ZIP 默认不包含这些资料。分享前请查看导出的模型和报告。

## 操作

1. 导入 YAML 模型或 SQLite/MySQL `CREATE TABLE` DDL。DDL 只解析表和字段，不执行。业务粒度、时间形态、关系和口径按缺口填写，并记录依据与责任角色。
2. 可选导入独立 SQLite 快照。只读连接运行模型中明确声明的数据约束；显示整个一致快照的扫描记录。没有约束声明、空表或未导入快照都不能显示为通过。
3. 在业务对象/数据集视图查看和编辑图。拖动只存布局，不改模型版本；节点连线需要注明关系落地方式、业务含义、键、基数和可遍历性。
4. 将使用问题存成一个明确场景。办事、政策适用和决策场景只保存业务合同和缺口，不能据此声称本工作台已办理业务、解释政策或给出方案建议。
5. 单表结构化聚合用本项目安全编译器试算。默认只表示执行；输入完整独立预期后才比较全部行与字段。
6. 可接本机既有演示引擎 `/api/model`、`/api/ask`。字段投影一致只说明已知 API 的已支持字段相符；未展示的本体扩展仍需目标消费者实际验证。
7. 下载交付 ZIP（语义 YAML、业务字典、场景、确认、问题及证据），或私人备份 ZIP（完整 SQLite 项目和导入快照）。

## 安全和边界

- 不访问外网、不加载第三方脚本，不收集凭据，不解析或执行 SQL 文件中的 DDL。API 只接受同源本机页面和临时会话令牌。
- 上传的 SQLite 快照只读打开，启用 `query_only` 和 SQLite progress deadline。SQL 来自单表编译器；不接受 SQL 字符串输入框。
- SQLite 最大文件 32 MB；查询最多取 500 行；消费者模型/应答受限为本机 Java HTTP JSON 接口、单次响应 4 MB、超时 15 秒。
- 不自动生成生产 SQL、不执行跨表查询、不下发写操作；也不做授权认证、标准符合性证明、生产权限证明、政策裁决、预测或优化。
- 每次模型/场景变更增加修订号。模型/快照不匹配或适用项目修订已改变时，相应证据过期。画布坐标单独保存在 SQLite，不使语义版本失效。

## 验证

`python -m unittest discover -s tests -v` 覆盖工作台 API、模型往返、证据状态和融合的 20 档不成熟输入；`python mocks/run_mock.py --all` 验证 13 个合成领域的端到端样例。
