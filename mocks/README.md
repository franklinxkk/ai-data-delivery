# mocks/ — 多领域快速 mock 测试包

本体建模与工具链**不绑定任何行业**。本目录用 5 个主流 AI+数据落地场景证明这一点：
每个领域都是一个自包含的最小工程（造数脚本 + semantic.yaml + gold 用例），
无需活引擎，一条命令端到端验证"建库 → 模型自检 → 评测集体检 → 口径编译 → 回归比对"全链路。

## 一条命令

```bash
python run_mock.py --all          # 5 个领域全跑
python run_mock.py --domain retail  # 只跑一个
```

每个领域的判定：G1 模型自检零 ERROR、G2 gold 体检零 ERROR、G3 回归零失败（声明式冲突豁免留痕）。
退出码 0 = 通过。当前状态：**5/5 全过**。

## 照抄一个新领域（10 分钟模板）

每个领域目录只有三个文件，照抄即可为你的行业建 mock：

1. **build_db.py** — 造数脚本。要求：确定性（禁止随机数，gold 必须可复算）、
   数据要有区分度（避免分组全相同）、写出后打印行数。
2. **semantic.yaml** — 迷你本体模型。要求：`check_model.py` 零 ERROR
   （grain/主键/角色合法/枚举字典/时间字段/ratio 分子分母/敏感标记一个不能少）。
3. **cases.json** — gold 用例 6~10 条。覆盖：单指标聚合、比率、筛选、分组、
   时间过滤、至少 2 条拒答（写操作/越界）。gold 数值用 SQL 复算后填入，不要手估。

用例辅助字段（`metric` / `sql`）只给模拟引擎用，`run_eval`/`gold_lint` 会忽略。
`finance/` 的 F06 是 `declared_conflict` 的写法范本（必须带 `ref` 决策出处）。

## 设计意图

- **领域无关自证**：合同 Schema（datasets/concepts/relationships/metrics）在 5 个行业
  同构适用，换行业只换内容不换结构。
- **无引擎自检**：模拟引擎 = reconcile_paths 的口径编译器直算 SQLite，
  因此 mock 同时验证了"filters+extra_where 全量编译"这一最易出错的环节。
- **新领域 PoC 的脚手架**：真实项目立项时，先照模板建一个 mock 跑通链路，
  再换成真实 DDL 与库连接——第一天就有回归基线。
