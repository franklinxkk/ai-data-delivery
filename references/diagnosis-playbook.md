## 第 0 步：排除环境层假故障

补丁后行为零变化、改了没生效——**先怀疑环境，再怀疑引擎**。实测高发三类：

1. **服务加载旧模型**：用 `probe_model.py --endpoint <地址> --model semantic.yaml` 核对运行时版本/数据集数/指标数/结构化数与本地权威源是否一致。
2. **构建产物是旧包**：rebuild.py 的新鲜度校验（产物旧于源码时拒绝 --skip-build）就是为此存在；手工排查可比对 jar 内 class 时间戳与源文件。
3. **端口被旧实例占用**：readiness 通过不代表是新实例，查进程命令行确认启动路径与端口归属。

排除环境层后再进入症状对照表。取证用 `capture_case.py --endpoint <地址> --question "<问句>" --out badcases/`——应答、检索命中、模型快照三件套一次落盘为登记卡，用户只有口头反馈时先用 `ingest_feedback.py` 入池。

## 症状对照表（8 类）

| # | 症状 | 典型表现 | 层定位 | 修复 |
| --- | --- | --- | --- | --- |
| 1 | 实体不识别 | 问"大区"无结果，问"区域"正常 | 模型层 | `patch_model.py syn` 补同义词（指标按 id；表别名用 `--dataset`；概念别名用 `--concept`） |
| 2 | 指标口径错 | 数值"差不多但不对"，差在过滤/时间/粒度 | 模型层 | `patch_model.py struct` 把全口径写进指标定义；**写入前必须 `--db` 对物理库验算候选口径有量且符合预期** |
| 3 | 维度过滤丢失 | "华东的销售额"返回全国数 | 模型层（维度键未挂）或引擎层（过滤未下推） | 先查模型维度键；键在而过滤丢 → 引擎层修下推 |
| 4 | 多跳/对比断裂 | "A 比 B 多多少"只答出 A | 引擎层 | 查询规划：子查询结果未传递 |
| 5 | 时间口径错 | "上月"算成"本季度" | 引擎层 | 时间解析器；注意与业务口径解耦（不变式 3） |
| 6 | 该拒未拒 | 问本体外的概念硬编答案 | 引擎层 | 拒绝判定阈值/覆盖检查；回归集补 refusal 用例 |
| 7 | 不该拒却拒 | 覆盖内的问题被拒 | 引擎层 | 覆盖检查过严，常因同义词未命中误判越界——先回症状 1 排除模型层 |
| 8 | 数据本身缺失 | 模型、引擎都对，底层表无此数据 | 数据层 | 不改模型不改引擎；回填数据或明确拒绝 |

## 层位验证动作

- **模型层验证**：同一实体的标准名能答、别名不能答 → 同义词缺失坐实。同一指标换个问法数值漂移 → 口径未自含坐实。
- **引擎层验证**：模型补丁后 case 行为零变化 → 先做第 0 步排除环境层，确认模型已生效再下沉引擎层。取引擎的查询计划/解析日志，比对语义输入与计划是否一致。
- **数据层验证**：用引擎生成的最终查询直连底层库执行，结果与期望一致 → 引擎执行错；不一致 → 数据层。

## 引擎不变式细则

1. **计划稳定性**：同一语义输入产出稳定唯一的查询计划。同义词命中顺序、字典序、并发都不得影响计划。检测：`plan_stability.py --endpoint <地址> --cases cases.json --times 10`，同一问句连跑 SQL 指纹必须一致（服务不可用会报"异常"而非误判稳定）。
2. **拒绝优先于猜测**：覆盖度检查不通过必须拒绝，并说明缺哪个实体/指标。检测：回归集 refusal 用例全过。
3. **时间与口径解耦**："今年/上月"由时间解析器统一折算为绝对区间，指标定义内禁止出现相对时间词。
4. **过滤下推**：所有维度过滤必须出现在最终查询的 WHERE 中。检测：抓最终查询文本，断言过滤条件在场。
5. **口径单源**：指标口径只存在于模型 YAML。检测：引擎代码全文搜索指标名，命中即违规。

## bad case 记录模板

登记卡由 `capture_case.py` 自动生成骨架（三件套已填），归因后回填 symptom/layer/fix/verify/expect；triage 出归因层后用 `suggest_card.py` 生成修订建议卡（证据/建议动作/影响面/回归占位）供评审；修复回归通过后 `promote_gold.py` 回流 gold 集（expect 未填拒绝入库，同 id 幂等覆盖）。口径类修复另跑 `reconcile_paths.py` 双路径对账确认指标路径与问数路径一致。

每个修过的 case 按此模板沉淀进 gold 集和交付说明：

```yaml
- id: bc-YYYYMMDD-NNN
  question: "原始问句（逐字）"
  symptom: 1        # 对照表症状编号
  layer: model      # model / engine / data / environment
  fix: 'patch_model.py syn 指标ID 大区'   # 附完整命令行，可复跑
  verify: 'SELECT COUNT(*) ... → 60 行'    # struct 类修复必填：物理库验算留痕
  expect:
    type: scalar    # scalar / rows / refusal
    value: 0
  regression_before: "72/74"
  regression_after: "73/74"
```

## 领域症状包

本手册保持领域中性。具体领域的特有症状与修法（如交通监管包：整词子串检索必须补自然问法、自指污染二次过滤、到期口径、精确键优先于桥接）**留在项目资产里**（决策日志/项目 playbook），不进本手册——换一个领域只换症状包，不换铁律与决策树。
