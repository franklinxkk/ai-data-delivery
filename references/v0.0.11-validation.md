# v0.0.11 本地迭代验证

日期：2026-11-01。基线：v0.0.10 / `f3dfc6a54cad6a471aeff66eca945c5d10d43b5f`。本轮是本地开发预览，尚未发布到 GitHub 或技能市场。

## 从实践吸收的改变

| 实际问题 | 本轮处理 | 保留边界 |
| --- | --- | --- |
| 已有数据结构仍重复录入本体 | derive_ontology + 工作台入口复用元数据，只补缺少的绑定 | 是可审阅候选，不自动证明业务身份、权限、基数或正式口径 |
| “逆关系”容易被理解为维护两套 | 解释同一关系的反向路径与聚合扩行风险 | 沿用原路径检查器，不增加 OWL 推理 |
| 稳定实体 uid 无法用于补齐定位 | 补齐流程同时识别 uid/name | 歧义/失效引用不自动重绑 |
| 当前状态指标被强迫填时间字段 | 显式 current 声明贯通补齐、lint、工作台编辑 | 不根据字段名猜当前/历史，不补隐式日期过滤 |
| 消费者模型不匹配还继续问数 | 检查失败后不再发送 /api/ask | 仅已知消费者字段投影，非完整语义等价或鉴权证明 |
| 空关联图可误报通过 | 无关系/查询规则保持 not_ready | 不把没有规则当数据正确 |
| 口径字典漏 filters | 字典及工作台导出显示条件，括号保留且/或关系 | 沿用原表达式，不新增通用 SQL 执行器 |
| 原始结果列表作为证据报告时崩溃 | 明确拒绝格式，并解释已有 run_eval 绑定路径 | 原始结果仍不是验收报告；不自动提高证据等级 |

另清理固定访谈题量、含糊的逆关系说明和未经本轮核实的竞品对比表。保留已有 CLI、工作台、历史报告与成熟度场景，不新增交付阶段、强制门禁或行业字典。兼容的 Skill 扩展信息收在 metadata 内，安全能力清单没有删除。

独立试用的初报曾把 extra_where 也列为遗漏；源码复核后确认旧实现已展示 extra_where，真正遗漏是 filters。已据证据修正，只关闭有依据的问题。

## 复现入口

仓库需按 requirements.txt 安装现有 PyYAML。运行：

```bash
python -m unittest discover -s tests -q
python mocks/run_mock.py --all
python workbench/serve.py --project tmp-browser-project --port 18841
```

浏览器开发验证脚本为 `maintainer/browser_v011.cjs`，需开发环境提供 Playwright/Chromium（或 BROWSER_PATH），在仓库根目录执行 `node maintainer/browser_v011.cjs`；WORKBENCH_URL 默认 `http://127.0.0.1:18841`。该脚本会替换独立测试项目的模型，仅对上述临时项目运行。结果与截图默认写 tmp-v0011，不包含生产数据。运行包不附带浏览器开发依赖。

原始浏览器日志、截图与独立试用过程存本地忽略目录，未混入运行包；可重复的测试与示例保留在仓库。打包工具校验逐文件内容及 CRC，BUILD.json 标明 development_preview，并逐文件列出摘要。
