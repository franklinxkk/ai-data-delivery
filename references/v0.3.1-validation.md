## Four-domain exercises

| Synthetic domain | Assets | Questions | Main counterexamples |
| --- | ---: | ---: | --- |
| Traffic | 17 | 8 | Person/vehicle/company/route/site/hazard/risk; tenant + source + original trip identity; employment handover; repeated stop order; hazard closure is not zero risk |
| Agriculture | 12 | 8 | Plot/season/batch; mixed harvest and split lineage; transfer does not add yield; unknown composition and irrigation thresholds |
| University | 14 | 8 | Natural person versus roles; enrollment attempts versus people; semester, withdrawal and historical department membership |
| Finance | 11 | 8 | Contract balance duplicated by collateral joins; same-value contracts; currency/date; missing FX and risk methodology; role is not authorization |

`maintainer/check_cross_domain.py` ran all **32 questions** through material import → prepared host task → authored proposal → explicit synthetic operator review → saved question check → fixed package → separate CLI reader. Checks preserved scope, dependencies, evidence revision/extraction/fragment, unknowns and execution boundaries. Checks neither published nor verified answers. Four complete packages retained all 54 assets.

The synthetic observation calculations used a separate toy Python oracle and fixed expected results. For example, tenant A has 2 source trips while the entire multi-tenant fixture has 3; harvest is 100 kg even after 100 kg of transfers; two natural people occupy three role rows; joined CNY balances total 300 incorrectly, while contract-grain balance is 200 and `SUM(DISTINCT amount)` incorrectly gives 100. These are not numeric results from the semantic reader.

The agriculture question “批次怎么追溯” originally missed “产品批次”. The label/alias matcher now accepts one shared Chinese bigram, while description-only matches still require two. The original candidate expectation was retained and passed after repair; a regression excludes an unrelated equipment description that only mentions 批次.

## Independent consumer

A fresh Agent received only four fixed ZIPs, observation files, questions and the Skill/reader guide. It did not read fixture models, expected answers, tests or implementation. It ran 12 CLI calls, selected dependencies and executed its own local Python calculations. The traffic, agriculture, university and financial sample results agreed with the fixed expectations. It preserved unknown batch allocation, risk reassessment, irrigation thresholds, currency conversion and authorization.

The financial `--as-of 2026-11-01` read reported `APPLICABILITY_UNKNOWN`; its CNY 200/USD 50 result remained a conditional exercise calculation, not proof of historical rule applicability. The consumer distinguished package revision from evidence-source revision. It reported verbose repeated evidence; reader guidance now advises preserving full JSON while reading bounded summaries and relevant source fragments. No measured token reduction or novice usability gain is claimed.

## OGS interoperability

- Official npm SDK `@neo4j/ontology-graph-spec@0.12.0`, Node 24.14.1, OGS schema 1.1.0. A real probe showed SDK 0.10.0 rejects schema 1.1.0; repository/main documentation and library releases cannot be treated as the same version.
- `maintainer/check_ogs.mjs` checked four domain projections and one separate attribute-boundary fixture. All five passed **core, labelled and consistentSchema** validation. A dangling relationship control was rejected with `missing_relation_to_node`.
- JSON and YAML roundtrips preserved all five native projections and opaque semantic/evidence payloads. The attribute fixture retained an integer above 2^53, `1.0`, `0`, `false` and `null` exactly in the string payload. Actual SDK checks found missing property names; the exporter now writes explicit generated design names.
- All four domain → Aura `data_model` → OGS conversions lost the custom semantic/evidence carrier and native aliases/metadata. `audit` correctly returned `changed_or_lost`. The attribute fixture's unknown decimal type was explicitly refused by Aura conversion; it was not silently changed to FLOAT or ANY.
- No source mappings or database keys were invented. `mappable` returned no issues on absent mappings; this is **not** import readiness. `wellConstrained` reported missing properties/constraints. No Neo4j server, live data, database constraints or business rules were executed. See [interop boundaries](neo4j-interop.md).

A final malformed-audit-input guard was then checked with the expanded **16-test OGS suite**, including 12 missing/invalid header subcases. The prior question-workflow implementation also passed isolated headless Edge checks for Chinese/English equipment review, graph edits, question save/reopen, gaps, concurrency, scoped publication/reload, ZIP delivery and 1600/1280 widths, with zero page errors. That browser run is retained evidence for the unchanged UI path, not a new four-industry browser/usability test.

The development archive is built from runtime paths only; its CRC, manifest hashes, source equality and extracted CLI smoke checks are verified before delivery. Tests, maintainer SDK/node_modules, project databases and private evidence are excluded. At the time of this local preview, the installed Skill and remote repository were unchanged. The source was subsequently pushed; this historical statement is not the current remote status.

## Unproven scope

Candidates are authored synthetic fixtures; this is not an extraction-accuracy benchmark, business sign-off, production authorization, action execution or proof of zero-threshold onboarding. Lexical discovery cannot verify complete question coverage. The earlier one-task Skill-versus-pure-Agent comparison found both preserved the equipment rules and limitations; neither that comparison nor this exercise establishes superior model accuracy or lower cost. Old fixed-package commands remain supported; earlier historical formats are not automatically migrated.
