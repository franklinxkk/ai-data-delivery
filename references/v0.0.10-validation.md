# v0.0.10 验证记录

日期：2026-10-03。验证对象：v0.0.9 源码基线上的本地工作台与用户提供的 `测试验证体系包_v2.0_20261003.zip` 的脱敏合成部分。

## 收到的测试包如何进入验证

- ZIP 内含重复目录和两份不同导航文档。本次采用主目录下的验证基线、20 个成熟度诊断案例及 5 个新增领域；未采纳 `verify_extract` 中旧版的 16 档/12 域/140 项说明为现状事实。最终工具链在当前源码上重新执行，不把 ZIP 中旧 `report.json` 当作本轮验证证据。
- 纳入 `mocks/diag_reform`、`edu_assess`、`elderly_care`、`green_factory`、`med_kpi` 五个领域模型及各自确定性数据库生成脚本、测试案例；纳入 5 个领域各 L0-L3 的 `semantic.yaml`、数据库脚本与诊断金标准。
- 纳入 `higher_vocational_diagnostic.yaml` 起步包：七类候选对象和五条仅语义关系。用户测试素材提及的责任状态、规则版本、时间口径需每个学校/项目自行核实，模板不把它们声称为国标规定。
- 高校客户原始素材、校名、账号、报价、私有文档和 SQLite 数据库未进入 Git、skill 包或公开验证报告。上游描述“五年、五十所高校”的真实积累未随这份 ZIP 提供原始明细，因此本版使用其抽象模型形态和脱敏合成案例验证工具，不声称已对五十所高校数据回测。

## 本版完成

本地单人工作台包含结构/快照/原始清单导入、双模式语义图与拖动布局、资产表单、语义缺口提问和依据留痕、业务场景/验收条件记录、模型 lint、SQLite 已声明约束扫描、关系键统计、单表指标编译执行、完整结果逐单元对拍、历史版本/恢复、问题单和交付/项目备份。原有 CLI 继续可用，skill 发布包收录 `workbench/` 运行时代码。

资产从唯一的 semantic.yaml 模型序列化状态编辑；YAML 扩展字段往返保留。布局独立写 SQLite，关系键兼容旧 `join_key_from/join_key_to` 并报告冲突。兼容现有 Java 消费者的已知模型投影与问数端点，不能证明其执行 ontology、constraints、模板、时间围栏或语义补齐声明。

SQLite 数据导入要求使用已 checkpoint/backup 的独立一致快照；仅复制仍处于 WAL 写入中的主数据库文件不能保证含已提交变更。该要求现在出现在工作台导入说明和保存的源文件记录中。

分级测试首次沙箱运行停在 Windows 临时目录写入：仅该隔离进程因沙箱新建临时目录后不可写而重试。改用临时目录写权限正常的本地运行环境后，20 档完成并全部通过；无业务代码或用户库因此修改。工具版本细节及逐档输出保存在验证方本地工作目录，包含的可再生 `.db` 不进入仓库。

## 审查中新增的产品边界

1. **结构完备与数据干净分开**：新增测试构造“L1 有四种脏数据，同时再删掉 grain”；工作台仍报告模型缺陷和数据违规，不让一个成熟度标签遮挡另一轴。
2. **场景必须给适用条件和独立预期**：指标、NL2SQL、办事、政策适用和分析决策显示各自不同的缺口；办事、政策裁决和分析决策目前只记录业务合同，不标记可执行。
3. **完整结果才叫对拍**：`[[11]]` 不会因为首单元格相同就满足 `[[11,25]]`；0、NULL、布尔和数字不混淆。只执行查询记为 `computed_only`。
4. **空集合不证明检查通过**：无 SQLite 快照时数据检查 `not_ready`；没有数据关联声明时关联检查 `not_ready`；没有声明规则不显示数据全量通过。
5. **标准版本仍需现场核对**：用户包给出的法规、国标和院校流程作为测试背景输入，并不代表符合性评价。尤其示例同时包含高校审核评估、高职诊改与不同领域标准，分域处理。
