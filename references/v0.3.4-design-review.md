# 0.3.4：让语义可交接、可检查、可持续维护

调研截止 2026-11-17。基线是 GitHub 的 0.3.3（`fe5314e`）。专家附件作为问题线索，逐项对照实际代码与合成练习；没有把其中的行动建议当作用户授权或已验证事实。

## 判断依据

业务问题要得到可信结果，至少需要四种不同的证据：**含义是什么、含义绑定哪些数据、当前调用被允许做什么、结果是否符合独立预期**。图谱连得通只能支持其中一部分；流畅的自然语言也不能补出缺失权限、时间或关联基数。

因此建模工具应替人完成资料整理、候选归并、依赖追踪与机械核验，把人的判断集中在会改变答案的歧义和例外。建模入口适合围绕问题和反例组织；图谱服务维护和解释；执行器承担数据访问与运算；相互引用同一语义源。此处是结合下列资料及代码实测作出的设计推论，不是各厂商共同发布的标准。

## 专家建议的处理与实际改动

| 观察或建议 | 0.3.4 处理 |
| --- | --- |
| 设备指标包只有7项，遗漏实际使用的4个字段 | 已复现并修复。样例候选新增稳定字段绑定，范围为11项；单表问题无需包含与查询无关的业务关系。字段变化进入影响路径并使旧观察失效 |
| 自然语言表达式不足以作为执行合同 | 增加指标上的 `query_plan`：数据集、列、粒度、映射、规则、所选关系、聚合、过滤、空值与时间约定；仍需语义审查，不自动证明文字与计划等价 |
| 增加 `query_control.json` | 已实施，固定到任务/模型/快照；服务预览、CLI 与工作台共享派生逻辑。篡改后即使重算文件哈希，也须通过内容重推校验 |
| 产出 executable/explain_only/blocked | 本版只产出 explain_only/blocked；没有真实执行器和授权握手就不给 executable。结构齐备另用 plan_status 表示 |
| 缺 path/grain 必须阻断 | 粒度绑定应明确；单表允许零跳。业务粒度不强行等同主键，多表关系不自动转为 join |
| 自动识别旧包 stale | 修正为“已知参考快照不一致”或“离线最新性未知”；不得在文件中写一个布尔值假装持续在线校验 |
| 包内字段/映射/关系闭包 | 只加入明确依赖，不把所有邻居带入；同步上下文边、影响路径、检查与发布范围 |
| PM/FDE 快速上手仍先进入旧 semantic.yaml 数值演示 | 两条入口改为同一业务问题与设备语义样例；旧数值工具保留为明确的独立可选路径 |
| 独立评审发现修改问题后仍展示旧下载 | 编辑/保存/项目修订变化时撤下当前页旧包入口；固定历史文件不改写 |
| 独立评审发现同源新增条款对接收方不可见 | 导出记录当时已知的更新来源修订，返回 SOURCE_REVISION_AHEAD；不外带新正文、不自动认定旧定义错误 |
| 查询控制易变成另一份难读 JSON | 原问题页显示字段数量、可读过滤/聚合、时间与缺项；细节折叠，检查后键盘焦点进入结果 |
| 通用 SQL 编译、JOIN 扇出检测、完整可视化编排、MCP 执行工具 | 未交付。它们需要独立运行时合同与真实数据验证；本次补丁不以空壳接口宣称具备这些能力 |

## 接下来怎样验证真正的增益

对交通、农业、高校和金融，先选一个真实问题，准备反例和独立预期。保持相同输入、权限与运行时，比较“仅原始资料”和“经核对语义+控制单”在错误答案、遗漏规则、反复澄清、维护返工和耗时上的差异。遇到双时间、跨币种、桥表或多来源身份，保留无法表达的条件；不能为通过而删掉反例。

本次修复有具体代码与回归支持；没有新的大规模行业盲测、真实用户易用性研究、生产授权联调或准确率结论。此前版本的多领域测试属于历史证据，不冒充 0.3.4 新增验证。

验证结果与交付基线见 [0.3.4 validation](v0.3.4-release-validation.md)。调用合同见 [query-control](query-control.md)。


## 发布前的工具定位收敛与审计清单

用户明确要求CLI优先、操作简单、链路短、用完即走。本轮调整不新增业务系统，保留统一资产及原保护，减少默认路径的管理步骤。

| 原问题 | 实际改动 | 证据 |
| --- | --- | --- |
| DDL导入后仍需接纳候选才能看到图 | 空图 `--seed-draft` 直接写入有来源的物理草稿；start --ddl与页面初始SQL导入复用它 | CLI及浏览器短链；初始资产全draft |
| 数据库第一次接入需要多页处理 | `scan --seed-draft`；页面保存连接后读取明确选表，成功直接打开草稿图 | SQLite CLI及真实表单验证 |
| 默认业务图把导入结构隐藏 | 只有物理资产时默认数据视图；保存过的视图偏好继续尊重 | Edge实际看见表字段外键 |
| CLI导出被问题或HTTP绕路阻断 | 新export薄入口复用原发布服务；默认全部有效模型，可显式选ID | sol20物理资产独立导出读取 |
| 界面过于像管理后台 | 移除常驻侧栏和工作区外壳，保留图谱/导入/导出三个主入口，其他放更多；材料与图谱细节按需展开 | 实际中英文及窄屏截图 |
| 说明书把问题验收放在首次入口 | 重写双语README/SKILL，首屏价值与两命令样例；问题、验收、数值诊断作为可选参考 | sol重新冷读调用，terra四角色模拟 |
| 减少操作可能覆盖已有成果 | 仅空图初始化；既有候选、人工编辑、修订和来源保护保留；输出文件防覆盖 | 非空seed、重复seed、未确认正式导出、已有输出保护用例 |
| 接收Agent要拼很多读取请求 | 可选问题包新增brief组合现有读取，保留分页、依据未读和执行限制；普通搜索复用Unicode规范化 | reader专项及独立接收试用 |
| 指标绑定只剩技术JSON | 可选绑定编辑表单复用原指标，明确记录核对理由，不支持的表达式保留原样 | 实际错误保留、0/false/null及重查发布验证 |
| 安全声明与功能能力易混淆 | 明确Read是预批准项，另列实际能力；维持本地接口保护、固定脚本、最小环境和安装包边界 | SECURITY、结构校验和原安全回归 |

以上保留了用户已确认的工具范围。没有引入新事实模型、权限系统、常驻Agent网关或新的审批前置步骤。实现和本地评测的具体范围见[验证说明](v0.3.4-release-validation.md)。
