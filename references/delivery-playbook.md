## 阶段门禁总览

```
立项 ──门禁A──> PoC ──门禁B──> 试点 ──门禁C──> 生产
 │               │              │               │
 指名工作流       happy path     真实用户         验收门槛全过
 gold 集 v0       跑通+会拒绝     bad case 闭环    运营留痕生效
```

任一门禁不达标，不进入下一阶段。跳门禁 = 把成本推迟到最贵的阶段爆发。

## 常见死因与预防

业界失败项目的高度共性死因，全部死在部署侧而非模型侧——逐条对应预防措施：

1. **范围不设边界** → 成本失控。预防：门禁 A 的越界清单 + 拒绝策略，拒绝判定进 gold 集。
2. **价值没有指名** → 验收时说不清有没有用。预防：指名工作流 + 基线指标（人工解答耗时），验收对照基线。
3. **跳过评估脚手架** → 演示惊艳、生产翻车。预防：gold 集在立项时建（v0），不是出事后补。
4. **口径飘在人脑和代码里** → 数字随问法漂移，信任崩塌。预防：五条铁律第 2、3 条；口径只住模型 YAML。
5. **bad case 没有归因纪律** → 修 A 坏 B，越修越不敢动。预防：模块二闭环 + 回归集单调不降硬约束。
6. **数据层问题改模型** → 南辕北辙。预防：归因决策树先验证层位再动手。
