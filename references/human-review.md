# 让人核验产出，而不只接收文件

工作台“交付与版本”可直接下载可视化验收页；交付ZIP中先打开 `00-human-review.html`。它由当前模型和已有证据生成，可离线阅读，不访问外部服务。思维导图用于导航，对象关系图表达关系，两者不能替代来源和结果核验。

| 谁在验 | 主要看什么 | 怎样发现错误 |
| --- | --- | --- |
| 数据产品经理/业务负责人 | 业务问题→对象→指标说明、包含/排除、单位、时间含义→独立预期和实际结果 | 对照原始业务定义，拿“应该纳入”和“不应该纳入”的记录核对。特别看重复、NULL、边界时间；未定的含义不能因为图好看就确认 |
| FDE/实施工程师 | 业务对象→物理表和字段→行粒度/主键→关系键和基数→执行快照/输入明细→目标消费者证据 | 核对真实数据结构和样本；确认N:1的一侧唯一、1:N不放大聚合、来源变化后旧结果失效。声明的映射不等于已执行的血缘 |
| 接收者共同核对 | 当前、过期、未验证、计算完成、预期一致、拒绝/失败 | 区分“这个数字算出来了”“与填写预期一致”“业务定义被认可”“生产消费者验收”四件事。没有报告不显示成已通过 |

页面支持可展开的思维导图、搜索、两种角色阅读入口、对象关系图、可读字段映射和预期/实际对照。原始定义折叠保留，FDE可展开追溯；来源、字段、关系、指标和报告没有再维护第二份业务真值。SVG导出属于已有对象关系图；思维导图随HTML保存，可用浏览器打印。无需安装思维导图软件。

## 一次具体核验：危货企业计数

先在纸上或对话中确定范围，再看工具结果。范围内企业标识是A、A、NULL：

| 定义 | 预期 | 人眼要检查的点 |
| --- | ---: | --- |
| 记录行数 | 3 | 两条A都是输入记录，NULL行也存在 |
| 企业标识非空数 | 2 | 重复A仍计入，NULL不计 |
| 去重企业标识数 | 1 | A只计一次；这只证明1个已知唯一标识，不代表数据完整地覆盖了全部企业 |

若业务要“企业数”，不能直接把3条记录说成3家企业，也不能把NULL记录静默忽略后宣称只有1家。应由有权业务负责人确认重复的含义、缺标识数据如何处理；必要时修数据后重算。另用其他主体、停业和普货记录检查排除规则。视图中当前明细只显示纳入记录，不凭空展示未执行的排除对拍。

可执行合成例子：

```bash
python examples/human-review/run_demo.py --out ./work/human-review-example
```

打开输出HTML，从“指标与计算”点三种计数，再看“结果与证据”。例子保留错误预期和过期报告，便于学习区分状态；已公开的演示答案不是独立业务验收。输出目录中的项目再次运行会拒绝覆盖，换新目录或用工作台继续。

已有模型也可生成：

```bash
python scripts/visualize_model.py --model semantic.yaml --report report.json --out human-review.html
```

没有报告可省略 `--report`，页面明确显示尚未验证。CLI报告须匹配当前模型；工作台报告沿用项目记录的模型/快照有效性。离线页只反映导出时的状态，源模型变化后应重新生成，不能把旧页面继续当最新证据。分享范围按接收者授权裁剪；页面与报告可能含业务数据。
