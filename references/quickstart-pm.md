# 数据产品经理 · 快速通道

你不需要会写 SQL。你的工作是**回答业务问题、确认口径、登记用户反馈**——命令让 agent 替你跑，你只把关内容。

## 你要参与的 4 件事

**1. 补齐会话里回答业务问题**
agent 会一批批问你：这表一行是什么（粒度）？这个指标含不含 X？时间按哪个字段算？
每个问题都带**候选项+依据**（agent 根据你给的材料推断的），你可以：
- 回"按候选确认"（它会记下是你确认的，不是 agent 自作主张）
- 回自己的答案 + 一句依据（依据会进审计记录）
- 回"暂缓"（它会标成待确认，继续卡着，不会偷偷放行）

**2. 看两个产出物**
- **口径字典**（dictionary.md）：每个指标怎么算的，人话版，可以直接发评审
- **语义图**（model.html）：双击打开，业务对象在上、物理表在下，点节点看详情，能导出 SVG 贴 PPT

**3. 发布前看清零报告**
`guide_model.py status` 的 `clearance`：`ready_for_validation: true` 才进入验证；
有 pending 就是还有问题没人认领——这就是你的待办清单。

**4. 用户说"数不对"时**
把原话给 agent："用户反馈：上个月重大隐患数量偏小"——它会走
反馈入池（ingest_feedback）→ 取证 → 归因（词表/引擎/口径三层）→ 修复后回归，
修完这条反馈会沉淀成评测用例，下次改版自动兜底。

## 你不需要看的

`check_*`、`run_eval`、`release_gate`、`rebuild` 等是 FDE 的验证/部署工具——
它们的结论（pass / not_ready + hint）会汇总给你，过程不用管。

## 一句话记住

**你的每个"确认"都有名字和依据，agent 的推断永远是候选，你点头才变成事实。**
