# 数据产品经理：把业务讲清，直接看结果

不用先写SQL、YAML或维护一套台账。向使用本skill的Agent说：

> 我需要统计【什么】，业务范围是【谁/什么时候/什么状态】，已有定义或资料在【路径】。请使用 ai-data-delivery，复用已有内容，先说明包含与排除，只问会改变结果的缺口；把业务定义、数值与明细放在我能查看的位置。

## 先看一次完整例子

请 Agent 运行下面命令并打开打印的网址（首次先安装 requirements.txt）：

```bash
python scripts/start.py --project ./work/pm-demo --demo
```

首页点“开始数值与明细练习”，已有字段会自动选好。点执行、切换三种指标，看到同一份A、A、空值记录为何得到3、2、1。再点“查看供Agent使用的上下文”，最后从“交付与版本”下载交付包。工作台自己不调用大模型；它保存和展示操作结果。

练习数据始终标为模拟。未填写独立预期只记计算完成；照抄练习答案不能证明真实系统验收通过。

## 真实工作只需参与这些判断

| 当前事情 | 你提供或确认 | Agent/FDE负责 |
| --- | --- | --- |
| 新指标/新场景 | 对象、用途、范围，典型应包含与排除的记录 | 从资料找映射，提出有依据的候选，准备模型与图 |
| 对定义有歧义 | 按实际授权决定哪种口径适用；没定的直接说明 | 记录依据，保持未定，不用默认值代替决定 |
| 核对结果 | 看数值和明细是否符合业务；提供能区分对错的例子 | 执行检查，解释0、NULL、无数据、失败的差别 |
| 用户反馈数不对 | 原话、实际结果、预期及可提供的样本 | 取证，定位来源/口径/引擎问题，修复后再验证 |

改“业务口径说明”不会自动改变公式。需要改统计范围、NULL或去重方式时，让Agent/FDE同步计算配置，再看更新后的数值和明细；别只验文字。

只有业务想法也能先推进定义。数据未提供、来源未接通或接口未实现时，交付草案和明确缺口，不制造“已通过”的结果。

## 成果在哪里、下次如何继续

给同事验收时，先下载“可视化验收页”或打开交付包的 `00-human-review.html`，从“指标与计算”点业务名称，不用先读机器文件。逐项核对范围、口径、单位、预期与实际，再处置未定问题。[具体数字例与验收方法](human-review.md)。

- 工作台“语义建模”：对象、字段、指标、关系和具体待补问题。
- “检查与试算”：数值、明细和历史结果；过期证据会提示重查。
- “交付与版本”：可读字典、语义模型、确认记录和证据；私人项目备份另外含导入附件。
- 关闭后用 `python scripts/start.py --project ./work/pm-demo` 重开；真实项目使用另一个目录，不覆盖演示或旧项目。

你的确认记录的是有权作出的业务决定，不能代替数据真实性或计算正确性的验证。正式交付是否接受，由项目的实际责任人按相应证据判断。
