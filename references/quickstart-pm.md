# 业务负责人：从一个问题开始

先准备真实问题、已有材料和一个能区分对错的例子。不必先学习本体语法或整理全库字段。

```bash
python -m pip install -r requirements.txt
python -X utf8 scripts/start.py --project ./work/equipment-pm --example equipment --language zh
```

1. 在“业务问题”写下“实验室 L 现在有多少台可借设备？”，保存问题。
2. 在“材料”先核对 DDL 的表和字段，再准备练习业务候选。对照原文确认范围、可借条件、去重和映射后接纳；练习候选是预先编写的合成材料，不是自动抽取结果。
3. 回问题页选择“可借设备数”，保存并检查。展开“问数交付边界”，看是否绑定正确字段、Lab L、在库、未停用与按编号去重。缺少当前库存就不能得出台数。
4. 在“问题验收”记录独立预期，例如另一实验室、停用设备不能计入；真正执行核验后才记录实际结果与证据。保存预期不等于通过。
5. “生成本问题的 Agent 包”交给接收方。后续改问题、字段或口径，重新检查并生成新包；历史包保持原样。

真实项目以新目录启动，不加 --example。让当前宿主处理：

> 用 ai-data-delivery，围绕【问题】复用【资料路径】中的定义，保存到【项目目录】。给我需要决定的范围、例外和字段含义，附原文与反例；技术绑定由你提出候选，我核对业务意义。不要补造缺失条件、数量或授权。

重开项目使用原目录并去掉初始化参数。专业维护可进入“语义图谱”；无需先逐个配置全部图节点。当前宿主负责推理，工作台没有内置模型。[问题流程](question-workflow.md) · [交付合同](query-control.md)

旧的 --demo 是独立数值与明细练习，适合核对已有执行模型；不作为本体建模首次入口，也不自动同步本页语义资产。
